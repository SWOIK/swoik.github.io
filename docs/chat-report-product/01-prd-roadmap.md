# 01 · PRD และ Roadmap — "ป้าเม้าท์" (ชื่อชั่วคราว)

> สถานะ: ร่างเพื่อตัดสินใจ · วันที่: 2026-11-19
> เอกสารนี้เป็นสมมติฐานที่ต้องพิสูจน์ ไม่ใช่ข้อเท็จจริง ตัวเลขทุกตัวในหมวด "เป้าหมาย" คือ **สมมติฐาน** ที่ต้องวัดจริง
> ที่มา: วิเคราะห์เว็บ whatbrandonthinks.com (อ่านหน้าสาธารณะเมื่อ 2026-11-19) ดูสรุปฟีเจอร์ในบทสนทนา

## 0. หลักการสำคัญ (อ่านก่อน)

1. **ทำเวอร์ชันของเราเอง ไม่ก๊อป** ใช้ "แนวคิด" ได้ (อัปโหลดแชท → AI เขียนรายงาน) แต่ต้องมีตัวละคร ชื่อ ภาพ โทนเสียง และข้อความของเราเอง ห้ามใช้ชื่อ Brandon / หน้าตา / ข้อความ / รีวิวของเขา ตัวละครคือ moat จริงของธุรกิจนี้
2. **ข้อมูลแชทเป็นข้อมูลส่วนบุคคลของคนที่สาม** (เพื่อน แฟน ครอบครัวที่ไม่ได้ยินยอม) และอาจมีข้อมูลอ่อนไหว (สุขภาพ เพศ ศาสนา) ต้องออกแบบ PDPA เป็นส่วนหนึ่งของผลิตภัณฑ์ ไม่ใช่งานเสริมตอนท้าย (ดูหมวด 7)
3. **ต้นทุน LLM ต่อรายงานเป็นข้อจำกัดหลักของโมเดลธุรกิจ** โดยเฉพาะตลาดไทยที่ราคาต้องต่ำกว่าต่างประเทศ (ดู `02` และ `03`)
4. **ก่อนสร้างระบบ ให้พิสูจน์ก่อนว่าคนไทยอยากจ่าย** ด้วย Wizard-of-Oz (ทำรายงานให้เองด้วยมือครึ่ง/เครื่องครึ่ง) กับแชทจริงของอาสาสมัคร

## 3. คุณค่าและตำแหน่งผลิตภัณฑ์

> **"ส่งแชทมา แล้ว [ตัวละคร] จะบอกว่าอะไรกำลังเกิดขึ้นจริง ๆ — แบบตรงไปตรงมา แต่หวังดี"**

หลักการเนื้อหา (ต้องเขียนเป็น guideline ของ prompt):
- ตัดสิน "แพตเทิร์น" ไม่ตัดสิน "คน" · ซื่อตรงแต่ไม่ใจร้าย · ไม่เข้าข้างผู้อัปโหลด
- ตลกเมื่อแชทตลก ลึกเมื่อแชทลึก (โทนปรับตามข้อมูล ไม่ใช่สองผลิตภัณฑ์)
- เมื่อเจอเนื้อหาร้ายแรง (ทำร้ายตัวเอง ความรุนแรง การล่วงละเมิด) **ไม่เล่นมุก** บอกตรง ๆ และชี้ไปความช่วยเหลือจริง (ดูหมวด 7.3)
- ระบุชัดว่าเป็น "ความเห็นจากข้อความ" ไม่ใช่ความจริง ไม่ใช่คำแนะนำทางการแพทย์/กฎหมาย/จิตวิทยา

## 5. เมตริกและเป้าหมายสมมติฐาน

> ตัวเลขเป้าหมายด้านล่างเป็น **ข้อสมมติฐานเพื่อใช้ตั้งเกณฑ์ตัดสินใจ** ไม่ใช่ค่าเปรียบเทียบจากอุตสาหกรรมที่ยืนยันแล้ว ให้ปรับหลังได้ข้อมูลจริงจาก Phase 0–1

**North Star:** จำนวนรายงานที่จ่ายเงินแล้วต่อสัปดาห์ (Paid reports / week)

| ช่วงกรวย | เมตริก | เกณฑ์ผ่าน Phase 1 (สมมติฐาน) |
|---|---|---|
| Landing → เริ่มอัปโหลด | start rate | ≥ 15% ของทราฟฟิกที่ตั้งใจ |
| เริ่ม → อัปโหลดสำเร็จ | upload completion | ≥ 50% (จุดตกหลักคือ export) |
| อัปโหลด → เห็น preview | preview rate | ≥ 90% |
| preview → จ่าย | **paid conversion** | **≥ 8%** (ตัวคูณสำคัญที่สุดต่อกำไร ดู `03`) |
| จ่ายแล้ว → รายงานถัดไป | repeat/continue rate | ≥ 20% ภายใน 30 วัน |
| รายงาน → แชร์ | share rate | ≥ 30% |
| แชร์ → ผู้ใช้ใหม่ | K-factor | ≥ 0.3 (ถ้า >0.5 คือ viral จริง) |
| คุณภาพ | "รายงานแม่น/ตรง" (ถามหลังอ่าน 👍/👎) | ≥ 80% 👍 |
| ความปลอดภัย | รายงานที่ถูกร้องเรียนข้อมูลผิด/ละเมิด | < 0.5% และตอบ ≤ 24 ชม. |
| ต้นทุน | LLM cost / upload (ทุก upload) | ≤ ฿12 (ที่แชทขนาดกลาง ดู `02`) |
| กำไร | contribution margin ต่อรายงานที่จ่าย | ≥ 60% หลังหักต้นทุน LLM ของ **ทุก upload** และค่าธรรมเนียมชำระเงิน |

## 7. ความเสี่ยงและมาตรการ

### 7.1 กฎหมายและความเป็นส่วนตัว (PDPA)
> ข้อนี้เป็นข้อมูลทั่วไปเพื่อวางแผนเท่านั้น **ต้องให้ทนายความตรวจ** ก่อนเปิดให้บริการจริง

- **ผู้ควบคุมข้อมูล**: เราเป็นผู้ควบคุมข้อมูลของผู้ใช้ และเป็นผู้ประมวลผลข้อมูลของบุคคลที่สามในแชท ต้องมีฐานทางกฎหมาย (ความยินยอม/ประโยชน์โดยชอบด้วยกฎหมาย) และเปิดเผยชัดเจนว่าส่งให้ผู้ให้บริการ LLM ประมวลผล
- **ข้อมูลอ่อนไหว** (สุขภาพ เพศ ศาสนา ฯลฯ) อาจอยู่ในแชท ต้องมี consent แบบชัดแจ้งในส่วนที่เกี่ยวข้อง และ minimization (เช่น ปิดบังเลขบัตร เบอร์ บัญชีธนาคารก่อนส่ง LLM)
- **ผู้เยาว์**: ตั้งเกณฑ์อายุขั้นต่ำ (เช่น 18+ หรือให้ผู้ปกครอง) และบล็อกสัญญาณชัดว่าแชทมีผู้เยาว์ตามนโยบายที่ทนายแนะนำ
- **ส่งข้อมูลข้ามประเทศ**: เลือกผู้ให้บริการที่ไม่ใช้ข้อมูลเทรนโมเดล มีข้อตกลงประมวลผลข้อมูล และบันทึกในนโยบาย
- **ลบข้อมูล**: ลบแชทอัตโนมัติ (แนะนำ ≤7 วันหลังรายงานล่าสุด และ ≤48 ชม. ถ้าไม่ซื้อ) สอดคล้องกับที่คู่แข่งทำ แต่ต้องทำให้ **จริง** รวม backup และ log
- **สิทธิ์ผู้ใช้**: ขอลบ/เข้าถึง/ถอนความยินยอมได้ภายใน SLA
- **ลิงก์แชร์**: อาจเผยข้อมูลบุคคลที่สาม ให้ปุ่มปิดชื่อ/ปิดลิงก์ และเตือนก่อนแชร์

### 7.2 ความเสี่ยงทางผลิตภัณฑ์
| ความเสี่ยง | มาตรการ |
|---|---|
| รายงานผิด/hallucination (ใส่คำพูดที่ไม่มีจริง) | ให้ LLM อ้าง quote พร้อม index ข้อความ แล้วตรวจด้วยโค้ดว่ามีจริง; รายงานระบุขอบเขต "อ่านจากข้อความเท่านั้น" |
| ผู้ใช้ใช้ไปสะกดรอย/ข่มขู่/ทำร้ายผู้อื่น | ไม่ให้ผลลัพธ์ที่เป็นการชี้นำให้ทำร้าย/ควบคุม; เงื่อนไขใช้งาน + ระบบรายงานการละเมิด |
| ผลกระทบต่อสุขภาพจิต (ถูกบอกว่า "เขาไม่รักคุณ") | โทน "ตัดสินแพตเทิร์น ไม่ตัดสินคน", ปิดท้ายด้วยข้อเสนอที่ทำได้จริง, ข้อความเตือน |
| ต้นทุน LLM บาน/ถูกโจมตี (อัปโหลดสแปม) | rate limit, ตรวจซ้ำ, CAPTCHA/OTP ก่อนประมวลผล, cap ข้อความ, งบรายวันพร้อม circuit breaker |
| ลอกเลียนง่าย | moat คือตัวละคร/แบรนด์/ข้อมูลฟีดแบ็ก/คอนเทนต์ ไม่ใช่เทคนิค |
| Chargeback | preview ที่ยุติธรรม, นโยบายคืนเงินชัด, คืนอัตโนมัติเมื่อระบบล้มเหลว |
| การพึ่งพาผู้ให้บริการ LLM รายเดียว | abstraction layer + fallback model |
| ลิขสิทธิ์/แบรนด์ | ตัวละครและข้อความของเราเอง ตรวจเครื่องหมายการค้าชื่อก่อนเปิดตัว |

### 7.3 โปรโตคอลเนื้อหาเสี่ยงสูง
- ตรวจจับ: ทำร้ายตัวเอง, ความรุนแรงในครอบครัว/คู่รัก, การล่วงละเมิด, ผู้เยาว์ → เปลี่ยนเป็นโหมดจริงจัง ไม่เล่นมุก ไม่วินิจฉัย
- ข้อความช่วยเหลือในไทย: สายด่วนสุขภาพจิต **1323**, เหตุฉุกเฉิน **191**, ศูนย์ช่วยเหลือสังคม **1300** (ให้ตรวจสอบหมายเลขและบริการล่าสุดกับหน่วยงานก่อนใช้จริง และพิจารณาเพิ่มช่องทางสำหรับความรุนแรงในครอบครัว/เด็กตามคำแนะนำของผู้เชี่ยวชาญ)
- ทดสอบด้วยชุดแชทสมมติที่ออกแบบมาเพื่อชนกรณีขอบก่อนเปิดตัวทุกครั้งที่เปลี่ยน prompt/โมเดล

## 8. คำถามเปิดที่ต้องตัดสินใจเร็ว
1. ชื่อแบรนด์และตัวละครสุดท้าย (ป้าเม้าท์เป็นเพียงตัวอย่าง) — ต้องเช็คเครื่องหมายการค้า/โดเมน/แฮนด์เดิลโซเชียล
2. ใครคือผู้ใช้เป้าหมายแรกที่จะเอาไปถึงตลาด (นักศึกษา/คนทำงาน/คู่รัก)?
3. จะเป็นบริษัทไทย (ภาษี/ใบกำกับ/PDPA ในประเทศ) หรือจดที่อื่น?
4. จะลงทุน mobile app เร็วแค่ไหน (App Store หักค่าธรรมเนียมสูงกว่าเว็บ จึงแนะนำเว็บ + PWA ก่อน)?
5. งบทดลองและงบ LLM รายเดือนสูงสุดที่ยอมรับได้ก่อนเจอ conversion จริง?
