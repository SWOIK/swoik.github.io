# 03 · โครงสร้างราคาและโมเดลรายได้ สำหรับตลาดไทย

> สถานะ: ร่างสมมติฐานเพื่อทดสอบ · วันที่: 2026-11-19
> **อ่านก่อน:** ทุกราคา (฿) ในเอกสารนี้คือ **ราคาตั้งต้นสำหรับทดลอง** ไม่ใช่ราคาที่พิสูจน์แล้ว ตัวเลขต้นทุนมาจาก `cost_model.py` ที่ใช้ราคาโมเดล/อัตราแลกเปลี่ยน/ค่าธรรมเนียมแบบ **สมมติ** (ดู `02` หมวด 5) ข้อมูลภาษี ค่าธรรมเนียมผู้ให้บริการชำระเงิน และกฎหมาย ต้องตรวจกับนักบัญชี/ทนายและเอกสารปัจจุบันของผู้ให้บริการก่อนใช้จริง

## 1. สิ่งที่ทราบจากคู่แข่ง (จากหน้าสาธารณะ)

| รายการ | ข้อมูลที่เว็บแสดง |
|---|---|
| รายงานเดี่ยว | **ราคาไม่ตายตัว** — ระบบทดสอบราคาตามประเทศ/ความยาว/ภาษา แสดงก่อนจ่าย (รวมภาษี); ไม่ประกาศราคากลาง |
| Preview ฟรี | อ่านต้นรายงานประมาณ 1/5–1/4 ฟรี ไม่ต้องใส่บัตร; ต้นทุนการวิเคราะห์เต็มเป็นของบริษัท |
| Ultimate Report | $99.99 ครั้งเดียว (อ่าน 2–5 แชท) |
| Membership | $29.99 / เดือน: คุยกับตัวละครบน WhatsApp + 5 รายงาน/เดือน + 1 Ultimate/เดือน (แสดง "มูลค่ารวม $174.94") |
| การชำระเงิน | ผ่าน Stripe (บัตร) ฯลฯ ไม่เห็นข้อมูลที่ชัดว่ารองรับวิธีจ่ายท้องถิ่นไทย (เช่น PromptPay) บนหน้าที่อ่านได้ |
| คืนเงิน | แทบไม่คืน (อ้างว่าเห็น preview แล้ว) ยกเว้นระบบสร้างรายงานล้มเหลว → คืนอัตโนมัติ |

อัตราแปลงอ้างอิง (สมมติ 1 USD = ฿35): Membership ≈ ฿1,050/เดือน, Ultimate ≈ ฿3,500 — **สูงกว่ากำลังซื้อทั่วไปของผู้ใช้เป้าหมายกลุ่มนักศึกษา/วัยเริ่มทำงานในไทยมาก** จึงไม่ควรแปลงตรง ๆ

## 2. ข้อจำกัดเชิงเศรษฐศาสตร์ที่ต้องเข้าใจก่อนตั้งราคา

จาก `02` หมวด 5: การให้ preview ฟรีทำให้ **ทุก upload มีต้นทุน LLM** แม้ไม่จ่าย ดังนั้นกำไรต่อ 100 uploads ขึ้นกับ paid conversion อย่างมาก

กำไรจากส่วนต่างหลังหักต้นทุน LLM ของ **ทุก** upload ต่อ 100 uploads (ยังไม่รวมค่าโฆษณา/ซัพพอร์ต/infra) ที่ราคา ฿59 / ฿99 / ฿149 และราคา LLM ตามสมมติฐานฐาน:

| paid conversion | S ฿59 | M ฿99 | L ฿149 |
|---|---|---|---|
| 3% | −478 | −325 | −943 |
| 5% | −379 | −153 | −682 |
| 8% | −231 | **+104** | −290 |
| 12% | −32 | +448 | +233 |
| 20% | +364 | +1,135 | +1,278 |

**ข้อสรุป:** ถ้า conversion จริง 3–5% ราคา ฿59–149 ขาดทุนที่ต้นทุน LLM อย่างเดียว ก่อนนับค่าโฆษณา ต้องมี 3 คันโยก: **ขึ้นราคา, ลดต้นทุนต่อ upload, หรือเพิ่ม conversion** — และต้องวัด conversion จริงก่อนสเกลทราฟฟิก

## 3. ข้อเสนอโครงสร้างราคา (สมมติฐานตั้งต้น)

### 3.1 รายงานเดี่ยว (ขายตามขนาดแชท — ราคาตายตัว โปร่งใส)

คู่แข่งใช้ dynamic pricing (ราคาต่างกันตามผู้ใช้) **ข้อเสนอสำหรับไทยคือใช้ราคาตายตัว 3 ระดับตามขนาดแชท** เพราะคนไทยแชร์ลิงก์ในกลุ่ม คุยเปรียบเทียบกันเร็ว ถ้าเห็นราคาต่างกันอาจเสียความเชื่อใจ (นี่เป็นข้อสันนิษฐานของผม ไม่ใช่ข้อมูลที่ยืนยัน → ให้ทดสอบ)

| ระดับ | ข้อความโดยประมาณ | ราคาตั้งต้นที่เสนอ | conv คุ้มทุน (LLM ×1.0) | conv คุ้มทุน (LLM ×2.0) |
|---|---|---|---|---|
| ไม่ซับซ้อน (S) | ≤ ~2,000 | **฿79** | 9.3% | 19.4% |
| กลาง (M) | ~2,000–8,000 | **฿129** | 5.2% | 10.5% |
| ยาว (L) | ~8,000–25,000 | **฿199** | 7.6% | 15.4% |

เปรียบเทียบกับชุดราคาที่ต่ำกว่า (฿59/฿99/฿149): conv คุ้มทุนของ S/M/L ที่ ×1.0 คือ 12.7% / 6.8% / 10.2% (และ 27.0% / 14.0% / 20.9% ที่ ×2.0) ชุดราคาที่สูงขึ้นช่วยให้มีขอบความปลอดภัยมากขึ้นมาก แต่ **ผลต่อ conversion ต้องวัดจริง**

ชุดที่สูงกว่านี้ (฿99/฿149/฿249) ให้ conv คุ้มทุน 7.3% / 4.4% / 6.0% ที่ ×1.0 — ใช้เป็นกรณีทดสอบ "ราคาสูง"

ทางเลือกลดความเสี่ยงอีกทาง: แทนที่จะขึ้นราคาเพียงอย่างเดียว ให้ **ตั้งกฎ fair use + ตรวจให้ upload เข้าข่ายก่อน** (ดูหมวด 6)

เมื่อเก็บ digest ไว้ (ได้รับความยินยอม) ต้นทุนฉบับต่อไปต่ำกว่ามาก ประมาณ ฿7 ที่ราคาสมมติฐาน ×1.0 (ใช้ writer ร่วมกับ digest/cached prompt เป็นหลัก — **ประมาณการจากสูตรเดียวกับ `cost_model.py` ไม่ใช่ค่าที่วัดจริง**)

|---|---|---|
| ต่อรายงาน (บริบทเพิ่ม/คำถามที่แนะนำ) | **฿59–79** | ต้นทุนต่ำ ผู้ใช้ผูกพันแล้ว (Upsell ที่กำไรสูง) |
| อัปเดตด้วยข้อความใหม่ | **฿59–99** ตามจำนวนข้อความใหม่ | |
| Persona เสริม (ต่างมุมมอง) | **฿69–89** | |
| แพ็ก 3 รายงานต่อเนื่อง | **฿149–179** (ลด ~20%) | ส่งเสริมการซื้อล่วงหน้า (prepaid credit) |

### 3.3 Ultimate (หลายแชท)

| รายการ | ราคาตั้งต้นที่เสนอ | หมายเหตุ |
|---|---|---|
| Ultimate (2–5 แชท) | **฿399–599** | ต้นทุนตัวอย่าง (3 แชท × 6,000 ข้อความ) ≈ ฿18.5 ที่ ×1.0, ≈ ฿37 ที่ ×2.0 → margin สูงมาก ราคาจริงขึ้นกับคุณค่าที่รับรู้ ไม่ใช่ต้นทุน |
| เหตุผลที่ไม่ตั้งตามต้นทุน | | ผลิตภัณฑ์ความรู้สึกสูง แต่ต้อง "ลึกจริง" ไม่งั้นเสียชื่อทั้งแบรนด์ |

(ราคา $99.99 ของคู่แข่ง ≈ ฿3,500 ซึ่งผมมองว่า **สูงเกินกำลังซื้อเฉลี่ยของตลาดเป้าหมายแรกในไทย** — สมมติฐานให้ทดสอบ)

### 3.4 Membership (เฟสหลัง; ช่องแชทผ่าน LINE OA)

| รายการ | เสนอ |
|---|---|
| ราคา | **฿299/เดือน** (ทดสอบ ฿249–399) |
| สิทธิ์ | คุยกับตัวละครบน LINE OA (มี fair-use cap) + รายงาน 3–5 ฉบับ/เดือน (ไม่สะสม) + ส่วนลด Ultimate |
| ต้นทุนประมาณการ (5 รายงาน M + 1 Ultimate + แชทโค้ช 300 ข้อความ/เดือน) | ≈ **฿180** ที่ ×1.0 · ≈ **฿359** ที่ ×2.0 |
| รายได้สุทธิต่อเดือน (฿299 หลัง VAT 7% และค่าธรรมเนียม 3.5%) | ≈ ฿270 |
| ผล | margin ≈ 33% ที่ ×1.0 · **ติดลบ** ที่ ×2.0 |

**ข้อสรุป:** ค่าใช้จ่ายหลักของ Membership คือ **แชทโค้ช** (ในโมเดลนี้ ≈ ฿115/เดือนที่ ×1.0) ไม่ใช่รายงาน จึงต้อง: (ก) ใช้โมเดลเล็กในการแชทปกติและเรียกโมเดลหลักเฉพาะตอนต้องการความลึก (ข) จำกัดข้อความ/วัน (ค) ลดจำนวนรายงานที่รวมให้เหลือ 3 ฉบับ หรือ (ง) ตั้งราคา ฿399 — และต้องวัดการใช้งานจริงของผู้ใช้กลุ่มหนักก่อนเปิด Membership

### 3.5 ฟรีและโปรโมชัน
- Preview ฟรี ~20–25% (ผูกกับ OTP อีเมล/LINE Login ก่อนเริ่มประมวลผล เพื่อลด abuse)
- **รายงานแรกลดราคา** (เช่น ฿49 ภายใน 24 ชม. หลังเห็น preview) — ทดสอบเป็น A/B ระวังไม่ให้สอนผู้ใช้ให้รอลดราคา
- Referral: ชวนเพื่อนได้เครดิต ฿20–30 ต่อคนที่จ่ายรายงานแรก (ต้นทุนเทียบกับค่าโฆษณา)
- กลุ่ม: "ฉันจ่ายแล้วแชร์ให้ทั้งกลุ่มอ่าน" เป็นพฤติกรรมธรรมชาติ → คิด "แพ็กกลุ่ม" (จ่ายคนเดียว ทั้งกลุ่มอ่านได้) แทนที่จะพยายามจำกัดการแชร์
- ฟีเจอร์ของขวัญ: ซื้อเครดิตให้เพื่อน/แฟน (วันเกิด วันวาเลนไทน์ ปีใหม่)

## 4. วิธีชำระเงินและค่าธรรมเนียม (ต้องตรวจก่อนใช้จริง)

| วิธี | บทบาท | หมายเหตุ |
|---|---|---|
| **PromptPay QR** | วิธีหลักของผู้ใช้ไทย ไม่ต้องมีบัตร | ผ่าน payment gateway ที่รองรับ (เช่น Stripe, Opn Payments, 2C2P, GB Prime Pay) ค่าธรรมเนียมมักต่ำกว่าบัตร |
| บัตรเครดิต/เดบิต | ผู้ใช้ต่างชาติ/ผู้ถือบัตร | ค่าธรรมเนียมสูงกว่า |
| TrueMoney Wallet / Rabbit LINE Pay | เข้าถึงกลุ่มอายุน้อย | ผ่าน gateway ที่รองรับ |
| App Store / Google Play | เฉพาะถ้าทำแอป native | ค่าธรรมเนียมสูงกว่าเว็บ จึงแนะนำเว็บ/PWA ก่อน |

- `cost_model.py` ใช้ค่าธรรมเนียมเฉลี่ยรวม 3.5% **เป็นสมมติฐาน** ให้แทนด้วยตัวเลขจริงจากผู้ให้บริการที่เลือก (ต้องรวมค่าธรรมเนียมคงที่ต่อรายการถ้ามี)
- ราคาในหน้าเว็บ **รวมภาษีแล้ว** และชัดเจนก่อนจ่าย
- ใช้ราคาจบด้วยเลขที่จ่ายง่ายด้วย QR (฿79, ฿129, ฿199) ไม่ต้องทดสอบเศษสตางค์
- ใบกำกับภาษี/ใบเสร็จ: ขึ้นกับสถานะการจดทะเบียนภาษีมูลค่าเพิ่ม (VAT) และประเภทลูกค้า → ถามนักบัญชี

## 5. การทดสอบและเรียนรู้ราคา (Phase 0–2)

| ขั้น | วิธี | เป้าหมาย |
|---|---|---|
| Phase 0 | **Van Westendorp** (4 คำถาม: ถูกจนไม่น่าเชื่อ / ถูกดี / เริ่มแพง / แพงเกิน) กับอาสาสมัคร 50–100 คนที่ได้อ่านรายงานตัวอย่างของตัวเอง | ช่วงราคาที่ยอมรับได้ต่อรายงาน |
| Phase 0–1 | **Gabor-Granger**: ถามว่า "ซื้อไหมที่ ฿X" ด้วยราคา ฿49 / ฿79 / ฿99 / ฿129 / ฿199 ต่อผู้ตอบหนึ่งราคา (between-subject) | เส้นอุปสงค์ |
| Phase 1 | **A/B ราคาจริง** บน landing/checkout (ราคาคงที่ต่อกลุ่ม; ไม่เปลี่ยนราคาให้ผู้ใช้คนเดียวกันเห็นต่างกัน) เช่น ฿79 vs ฿99 สำหรับแชทขนาดกลาง | conversion × ราคา = รายได้ต่อ upload |
| Phase 1–2 | ทดสอบ **ขนาด preview** (15% / 25% / 35%) และ **ความยาวรายงาน** | ดู conversion และความพึงพอใจหลังอ่าน |
| Phase 2 | ทดสอบ bundle, ราคาฉบับต่อเนื่อง, Referral | LTV/CAC |

**KPI ราคาหลัก:** รายได้สุทธิต่อ 100 uploads (รวมต้นทุน LLM ทั้งหมด) · conversion · ARPU · repeat rate · refund/chargeback rate · LTV/CAC
**ข้อห้าม (จริยธรรม):** ห้ามใช้ dark pattern เช่น นับถอยหลังปลอม, ปิดบังเงื่อนไขหลังจ่าย, ทำให้รายงานฟรีขาดตอนจนอ่านไม่รู้เรื่อง ต้องให้ preview ที่มีคุณค่าจริง และนโยบายคืนเงินที่ชัดเจน (คืนเต็มจำนวนเมื่อรายงานไม่ถูกส่ง/เสีย)

## 6. กฎ Fair Use และการป้องกันต้นทุน
- จำกัดจำนวน upload ฟรี/วัน/บัญชี/อุปกรณ์ + OTP/LINE Login ก่อนประมวลผล
- เพดานข้อความต่อ upload (แนะนำ 25,000 ข้อความล่าสุดในช่วง MVP) และแจ้งผู้ใช้ชัดเจน
- ตรวจ hash ไฟล์ซ้ำ ไม่ประมวลผลซ้ำฟรี
- งบ LLM รายวัน + circuit breaker; แจ้งเมื่อ margin ต่อวันต่ำกว่าเกณฑ์
- ระบบเครดิต (prepaid) แทน "ฟรีไม่จำกัด" ทุกกรณี

## 7. Unit economics checklist (ก่อนเปิดตัว)
- [ ] วัดจำนวนโทเคนจริงต่อข้อความไทยกับ tokenizer ของโมเดลที่เลือก (ค่าตั้งต้นในสคริปต์: 22 โทเคน/ข้อความ)
- [ ] ยืนยันราคาโมเดลและอัตราแลกเปลี่ยนปัจจุบัน แก้ `cost_model.py` แล้วรันใหม่
- [ ] วัด `model_cost_usd` ต่อรายงานจริงจาก pilot (ดู schema ใน `02`) แล้วเทียบกับสูตร
- [ ] วัด paid conversion จริงที่ราคาแต่ละระดับ
- [ ] ยืนยันค่าธรรมเนียมชำระเงินจริงต่อวิธี (PromptPay/บัตร/Wallet)
- [ ] คำนวณ CAC ต่อช่องทาง (อินฟลูเอนเซอร์ TikTok/IG, SEO, referral)
- [ ] นับต้นทุนซัพพอร์ต/ระบบ/ค่าแรง (ไม่อยู่ในโมเดลนี้)
- [ ] ปรึกษานักบัญชี: จดทะเบียน VAT, การออกใบกำกับ, การรับรู้รายได้ (credit/prepaid)
- [ ] ปรึกษาทนาย: ข้อกำหนดการคืนเงิน/ยกเลิก (กฎหมายคุ้มครองผู้บริโภคไทย), ข้อความเงื่อนไขราคา
